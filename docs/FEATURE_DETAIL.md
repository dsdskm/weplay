# WePlay 기능 정리

## 0. 공통 기능

### 완료

- **기능 승인 흐름**: 그룹이 기능을 신청하면 MASTER가 승인하거나 거절하고, 승인된 기능은 회수할 수 있습니다. 회수된 그룹은 다시 신청할 수 있습니다.
- **기능 카테고리**: 인정·보상(이달의 사원, 칭찬 카드, 포인트·배지), 소통(자유 게시판, 롤링페이퍼, 랜덤 설문), 모임·이벤트(회식 투표, 간식 쏘기, 마니또), 게임(미니게임, 사진·영상 미션). 정의는 `FEATURE_CATEGORIES`(shared)이고, user-web 좌측 메뉴·기능 신청·활동 기능 설정과 system-web 기능 관리(카테고리 필터 칩 + 섹션별 그리드)에 적용됩니다.
- **기본 탑재 (MASTER)**: 기능 카드의 `기본 탑재` 스위치를 켜면 그룹이 신청하지 않아도 모든 그룹에서 바로 쓸 수 있습니다(user-web에는 `기본 제공`으로 표시). 켤 때 대기 중인 신청은 자동 승인합니다. 그룹 목록에서 특정 그룹만 회수할 수 있고, 회수된 그룹은 다시 신청해 승인받아야 합니다. 해제하면 신청·승인 기록이 없는 그룹은 더 이상 쓸 수 없습니다(`FeatureConfig.isDefault`).
- **기능 전역 활성/비활성 (MASTER)**: system-web `기능 관리`는 기능별 카드 그리드로 보이고, 카드의 스위치로 기능 전체를 켜고 끕니다. 끄면 모든 그룹에서 메뉴가 사라지고 신청도 막히지만, 승인 기록과 데이터는 남아 다시 켜면 그대로 돌아옵니다(`FeatureConfig`).
- **관리자 범위**: 그룹 ADMIN과 팀 ADMIN을 모두 관리자로 봅니다. 기능 관리 화면과 관리 메뉴에 공통 적용합니다.
- **목록 페이지네이션**: 모든 목록을 페이지로 나눠 보여 줍니다.
- **확인 모달**: `window.confirm`, `alert`, `prompt`를 쓰지 않고 공통 모달로 처리합니다. 삭제와 숨김은 확인을 거칩니다.
- **감사 로그**: 기능 승인·회수, 이달의 사원 선정·추천 삭제, 칭찬 수정·숨김 등 주요 변경을 남깁니다.
- **팀 상세 분리**: 팀 상세는 구성원 공통 화면이고, 팀 정보 수정·가입 설정·역할 관리·삭제는 관리자 화면(`팀 관리`)으로 나눴습니다.
- **그룹·팀 권한 규칙 테스트**: `node scripts/test-rules.mjs` (17개)
- **샘플 데이터 스크립트 구조**: 기능별로 `generate-feature`, `generate-contents`, `delete-feature`, `delete-contents`를 둡니다.

### 미완료

- **이메일 발송**: Gmail SMTP로 보냅니다 (`MAIL_DRIVER=gmail`). 회원가입과 이메일 변경은 6자리 인증번호(10분 유효, 1분 간격 재발송, 5회 틀리면 재발송 필요)를 받고, 비밀번호 찾기는 인증번호를 메일로 받아 확인한 뒤 새 비밀번호를 설정합니다. 시스템 콘솔의 `API 테스트` 메뉴에서 발송 설정을 확인하고 테스트 메일을 보낼 수 있습니다.
- **알림**: 칭찬을 받았을 때, 이달의 사원이 공개됐을 때, 추천이 선정됐을 때 알려 주는 인앱 알림과 푸시가 필요합니다.
- **파일 저장 고도화**: 업로드 파일은 서버 로컬 폴더에 저장합니다. 운영에서는 S3 같은 객체 저장소와 용량·바이러스 검사가 필요합니다. 칭찬 화면의 첨부 버튼은 아직 연결하지 않았습니다.
- **자동 선정 스케줄러**: 지금은 화면을 열 때 공개일 지난 달을 자동 선정합니다. 공개일 0시에 맞춰 돌도록 바꿔야 합니다.
- **승인 흐름 테스트**: 가입 요청 승인 경로가 자동 테스트에 빠져 있습니다.
- **브라우저 전체 점검**: system-web과 user-web 전 화면을 실제로 확인하지 않았습니다.
- **활동 기능 6종 브라우저 점검**: 롤링페이퍼, 사진 미션, 회식 투표, 랜덤 설문, 간식 쏘기, 게시판은 타입 검사까지만 했고 실제 화면에서 눌러 보지 않았습니다.
- **샘플 데이터 갱신**: 칭찬 샘플은 익명 카드를 포함하지만, 숨김 카드와 반응은 만들지 않습니다. 이달의 사원 샘플은 칭찬 한도와 무관합니다.

## 1. 이달의 사원 (완료)

기능 승인 후 그룹 단위로 사용합니다. 구성원 화면은 `이달의 사원`, 관리자 화면은 `이달의 사원 관리`입니다.

### 구성원

- **추천**: 아직 공개되지 않은 달을 대상으로 한 달에 한 명을 추천합니다. 사유는 필수이고, 본인은 추천할 수 없습니다. 다시 추천하면 바뀝니다.
- **공개**: 그룹 공개일(매월 1~28일, 기본 1일) 0시부터 결과를 보여 줍니다. 공개 전에는 직전 달 결과를 보여 줍니다.
- **공개 예정 D-day**: 홈 카드에 다음 공개일까지 남은 날짜를 표시합니다.
- **월 선택**: 지난 달 결과를 월 선택기로 봅니다. 공개되지 않은 달은 선정자를 숨깁니다.
- **명예의 전당**: 공개된 달 기준으로 가장 많이 선정된 사람과 가장 많이 추천받은 사람을 보여 줍니다. 동점이면 모두 표시합니다.
- **선정 내역**: 구성원마다 🏅 이달의 사원 배지와 선정 횟수를 보여 줍니다.
- **이번 달 배지**: 이번 달 공개된 이달의 사원은 구성원 목록에 🏅로 표시됩니다.
- **추천 사유**: 선정자별 추천 사유를 추천자 이름 없이 내용만 보여 줍니다.
- **댓글**: 공개된 선정자에게 댓글을 남기고, 작성자 본인이 수정하거나 삭제할 수 있습니다.

### 관리자 (그룹 ADMIN·팀 ADMIN)

- **월별 집계**: 최근 6개월의 추천 수, 상위 후보, 선정 결과를 봅니다.
- **추천 내역**: 추천자와 사유를 보고, 부적절한 추천을 삭제합니다.
- **추천 참여 현황**: 추천 참여 인원과 미추천 구성원을 보여 줍니다.
- **선정**: 추천받은 구성원 중에서 선정 인원만큼 고르고 한 줄 소개를 남깁니다. 칭찬 카드 받은 수도 함께 봅니다.
- **자동 선정**: 공개일이 지나도 선정하지 않은 달은 추천 상위 N명이 자동 선정됩니다.
- **댓글 관리**: 월별 댓글을 보고 삭제합니다.
- **설정**: 공개일과 선정 인원(달마다 1~5명)을 정합니다.
- **범위**: 그룹 ADMIN은 그룹 전체를 봅니다. 팀 ADMIN은 담당 팀 구성원 범위의 추천, 후보, 댓글, 칭찬, 미추천 현황만 보고 선정도 그 범위에서만 합니다.

### 규칙

- 추천과 선정은 활성 계정 구성원만 대상으로 합니다.
- 기능이 승인되지 않은 그룹에서는 메뉴와 API가 막힙니다.

### 샘플 데이터 (개발용)

`scripts/feature/employee-of-the-month/`

- `generate-feature.sh [groupId]`: 기능 승인 (MASTER 승인 생략)
- `generate-contents.sh [groupId] [publishDay] [winnerCount] [months] [nominatorsPerMonth] [commentsPerWinner]`: 추천, 선정, 댓글 생성
- `delete-feature.sh <groupId|--all> [-y]`: 기능 신청·승인 삭제
- `delete-contents.sh <groupId|--all> [-y]`: 추천, 선정, 설정, 댓글 삭제

## 2. 칭찬 카드 (완료)

기능 승인 후 그룹 단위로 사용합니다. 구성원 화면은 `칭찬 카드`, 관리자 화면은 `칭찬 관리`와 `칭찬 카드 설정`입니다.

### 구성원

- **보내기**: 활성 구성원에게 보냅니다. 대상은 이름이나 이메일을 입력해 드롭다운에서 고릅니다. 본인에게는 보낼 수 없고, 익명으로 보낼 수 있습니다.
- **일별 한도**: 하루에 보낼 수 있는 칭찬 수를 제한합니다. 기본 3개이고, 관리자가 1~20개 사이에서 정합니다. 기준은 KST 0시입니다.
- **피드**: 전체 칭찬을 최신순으로 보여 줍니다. 내용 검색, 받은 사람, 보낸 사람, 기간으로 거를 수 있습니다. 익명 카드는 보낸 사람 본인과 관리자만 보낸 사람을 확인할 수 있습니다.
- **내 칭찬**: 보낸 칭찬과 받은 칭찬을 각각 페이지로 보여 주고, 받은 수·보낸 수·오늘 남은 수를 상단에 표시합니다.
- **수정**: 보낸 칭찬의 내용을 고칠 수 있습니다. 익명 여부는 바꿀 수 없습니다.
- **삭제 불가**: 모든 계정 유형에서 칭찬 카드를 삭제할 수 없습니다.
- **반응**: 받은 칭찬에 👏 ❤️ 🎉 😊 중 하나로 반응합니다. 누가 눌렀는지는 보이지 않고 개수만 보입니다. 본인이 보낸 칭찬과 숨겨진 칭찬에는 반응할 수 없습니다.

### 관리자 (그룹 ADMIN·팀 ADMIN)

- **칭찬 카드 설정**: 하루 보낼 수 있는 칭찬 수를 정합니다.
- **칭찬 관리**: 날짜별 전체 칭찬을 보여 줍니다. 익명 칭찬도 보낸 사람이 보입니다. 보낸 사람, 받은 사람, 숨김 여부로 거를 수 있습니다.
- **숨김**: 부적절한 칭찬을 숨깁니다. 숨긴 칭찬은 구성원 화면 어디에도 보이지 않고, 해제할 수 있습니다.
- **월별 참고**: 칭찬 카드 받은 수는 이달의 사원 관리 화면에서 월별로 보여 줍니다.

### 규칙

- 칭찬은 월별로 나누지 않습니다. 월은 이달의 사원 참고용으로만 씁니다.
- 기능이 승인되지 않은 그룹에서는 메뉴와 API가 막힙니다.

### 샘플 데이터 (개발용)

`scripts/feature/compliment-card/`

- `generate-feature.sh [groupId]`: 기능 승인 (MASTER 승인 생략)
- `generate-contents.sh [groupId] [months] [sendRate]`: 칭찬 생성. 일별 한도를 지키고 익명 카드를 약 20% 섞습니다.
- `delete-feature.sh <groupId|--all> [-y]`: 기능 신청·승인 삭제
- `delete-contents.sh <groupId|--all> [-y]`: 칭찬 카드 삭제

## 3. 포인트·배지 (완료)

기능 승인 후 그룹 단위로 사용합니다. 구성원 화면은 `포인트·배지`입니다.

- **포인트**: 활동 기록에서 계산합니다. 칭찬 보내기 2점, 받기 3점, 이달의 사원 추천 1점, 선정 10점, 댓글 1점입니다. 활동 기능은 롤링페이퍼 메시지 1점, 미션 제출 2점·주최 3점·베스트 컷 5점, 회식 투표 1점, 설문 응답 1점·등록 2점, 간식 참가 1점·당첨 3점, 게시글 2점·댓글 1점입니다. 숨겨진 칭찬은 제외하고, 이번 달 선정은 지난 달까지만 셉니다.
- **배지**: 활동 수가 목표에 닿으면 얻습니다. 첫 칭찬, 칭찬 메이커, 인기쟁이, 추천 요정, 이달의 사원, 소통왕에 더해 롤링페이퍼 작가, 미션 도전자, 미션 주최자, 베스트 컷, 투표왕, 설문 응답가, 설문 기획자, 간식 기부천사, 글쓴이, 댓글러가 있습니다. 베스트 컷과 간식 기부천사는 이달의 사원처럼 얻을 때마다 횟수가 늘어납니다. 이달의 사원 배지는 선정될 때마다 받고, 획득 횟수를 함께 보여 줍니다.
- **홈 표시**: 홈 화면에 내 포인트, 획득 배지, 최근 포인트 내역(칭찬·추천·선정·댓글·관리자 조정)을 보여 줍니다. 포인트 순위는 없습니다.
- **배지·포인트 표시**: 구성원 목록에 포인트와 획득 배지가 나오고, 팀원 목록에는 획득 배지가 나옵니다.
- **기본값 설정 (MASTER)**: 활동별 점수와 배지 목표, 사용 여부를 정합니다. 그룹이 따로 설정하지 않으면 이 값이 적용됩니다.
- **그룹 설정 (관리자)**: 그룹 관리자(그룹 ADMIN·팀 ADMIN)가 점수와 배지를 바꿀 수 있습니다. 기본값으로 되돌릴 수도 있습니다.
- **직접 부여·차감 (관리자)**: 구성원에게 점수를 더하거나 빼고, 사유를 남깁니다. 내역은 구성원 화면에 조정 점수로 나옵니다.
- **규칙**: 공지 확인, 투표, 행사 참여 같은 활동은 아직 없어서 포인트에 넣지 않았습니다.

## 4. 마니또 (완료)

기능 승인 후 그룹 단위로 사용합니다. 구성원 화면은 `마니또`입니다.

- **시작·종료**: 관리자(그룹 ADMIN·팀 ADMIN)가 시작하고 종료합니다. 시작 시각과 종료 시각을 정할 수 있고, 종료 시각을 비우면 직접 종료할 때까지 진행합니다.
- **참가자 선택**: 전체 구성원 또는 직접 고른 구성원만 참가합니다. 관리자도 참가를 선택할 수 있습니다.
- **배정**: 참가자끼리 무작위로 배정합니다. 자기 자신은 제외하고, 서로 마니또가 되는 것은 허용합니다.
- **나의 마니또**: 나만 내 마니또가 누구인지 봅니다. 마니또에게는 내 이름이 보이지 않습니다.
- **익명 채팅**: 나의 마니또와 익명으로 메시지를 주고받습니다. 나를 맡은 사람과도 익명으로 주고받습니다.
- **관리자 조회**: 관리자가 참가하지 않은 회차에서만 전체 마니또 현황을 봅니다. 참가 중인 관리자는 자기 마니또만 봅니다.
- **채팅 방식**: 3초마다 새 메시지를 가져오는 방식입니다. 실시간 푸시는 SSE로 바꿀 수 있습니다.

## 5. 롤링페이퍼 (완료)

기능 승인 후 사용합니다. 구성원 화면은 `롤링페이퍼`, 설정은 `활동 기능 설정`입니다.

- **만들기**: 한 사람을 대상으로 제목, 안내 문구, 종이 색(노랑·분홍·하늘·연두), 마감 시각을 정해 만듭니다. 대상 본인은 만들 수 없습니다. 설정에서 구성원 생성을 끄면 관리자만 만듭니다.
- **보기**: 그룹 모두에게 공개됩니다. 종이 위에 색색의 포스트잇이 조금씩 기울어진 채 붙어 있어 실제 롤링페이퍼처럼 보입니다.
- **쓰기**: 포스트잇 색을 고르고 메시지를 남깁니다. 익명으로 쓸 수 있고, 한 사람이 쓸 수 있는 개수와 글자 수는 설정값입니다. 내 메시지는 지울 수 있습니다.
- **관리자**: 마감하거나 삭제합니다. 마감하면 더 쓸 수 없습니다.
- **설정**: 구성원 생성 허용, 사람당 메시지 수(기본 3), 글자 수(기본 200), 익명 허용.
- **포인트·배지**: 메시지 1점, `롤링페이퍼 작가`.

## 6. 사진·영상 미션 (완료)

- **주최 순서**: 기본은 돌아가며 합니다. 주최 횟수가 가장 적은 사람, 같으면 마지막 주최가 가장 오래된 사람이 다음 차례입니다. 설정에서 `누구나`, `관리자만`으로 바꿉니다.
- **진행**: 주최자가 주제, 설명, 참고 사진·영상, 마감을 정해 던집니다. 다른 구성원이 사진·영상을 올립니다(사람당 제출 수 제한).
- **베스트 컷**: 주최자(와 관리자)가 베스트 컷을 고르고 확정하면 미션이 끝납니다. 개수는 설정값입니다.
- **파일**: 이미지와 영상을 서버에 올립니다(최대 `MAX_UPLOAD_MB`, 기본 30MB). 영상 허용 여부는 설정입니다.
- **설정**: 주최 방식, 사람당 제출 수(3), 베스트 컷 수(1), 기본 진행 시간(72시간), 영상 허용.
- **포인트·배지**: 제출 2점, 주최 3점, 베스트 컷 5점, `미션 도전자`, `미션 주최자`, `베스트 컷`.

## 7. 회식 투표 (완료)

- **후보 장소**: 네이버 지역 검색으로 찾아 등록하거나 직접 입력합니다. 그룹 공통 장소와 팀 전용 장소를 나눕니다.
- **지도**: 네이버 지도에 후보 장소를 마커로 보여 줍니다. 지도 키가 없으면 안내 문구와 목록만 나옵니다.
- **투표**: 날짜 후보와 장소 후보를 만들고, 구성원이 날짜와 장소에 투표합니다. 결과 막대와 1위 표시가 나옵니다. 팀 투표는 그 팀 구성원만 봅니다.
- **관리자**: 투표 생성(설정에 따라 구성원도 가능), 마감, 삭제.
- **설정**: 구성원 투표 생성, 구성원 장소 등록, 날짜 복수 선택(켜짐), 장소 복수 선택(꺼짐), 기본 투표 기간(72시간).
- **포인트·배지**: 투표 참여 1점(투표당), `투표왕`.
- **환경변수**: `NAVER_SEARCH_CLIENT_ID`, `NAVER_SEARCH_CLIENT_SECRET`(서버, 장소 검색), `NEXT_PUBLIC_NAVER_MAP_CLIENT_ID`(user-web, 지도).

## 8. 랜덤 설문 (완료)

- **등록**: 누구나 제목, 설명, 질문(단일 선택, 복수 선택, 서술형, 별점)을 만듭니다. 익명 응답 여부를 고릅니다.
- **시작 방식**: `직접 시작`은 등록자나 관리자가 누릅니다. `랜덤`은 승인 후 설정한 기간 안의 무작위 시각에 자동으로 시작합니다.
- **승인**: 설정에 따라 관리자가 승인하거나 반려(사유 입력)합니다. 관리자가 만든 설문은 바로 대기 상태가 됩니다.
- **응답과 결과**: 한 사람이 한 번 응답합니다. 결과는 응답자·등록자·관리자에게 보이고, 종료 후 또는 진행 중에도 공개할지 설정합니다. 선택형은 막대, 별점은 평균, 서술형은 목록으로 나옵니다.
- **상태 전환**: 스케줄러 없이 목록·상세를 열 때 시간이 된 설문을 시작하고, 기한이 지난 설문을 종료합니다.
- **설정**: 승인 필요(켜짐), 랜덤 시작 범위(7일), 진행 시간(48시간), 최대 질문 수(10), 결과 공개 시점.
- **포인트·배지**: 응답 1점, 등록 2점, `설문 응답가`, `설문 기획자`.

## 9. 간식 쏘기 랜덤 (완료)

- **진행**: 게임을 만들고 참가자를 모은 뒤 시작합니다. 시작하면 칸이 참가자 수만큼 만들어지고, 참가자가 한 번씩 칸을 골라 한 장씩 뒤집습니다. `당첨` 또는 `다음 기회`가 나옵니다.
- **공정성**: 당첨 칸은 시작 때 섞어 정하고, 뽑기 전에는 서버가 결과를 내려 주지 않습니다. 한 사람이 한 번만, 이미 뽑힌 칸은 뽑을 수 없습니다.
- **범위**: 그룹 전체 또는 팀 한정 게임입니다.
- **설정**: 구성원 생성 허용, 기본 당첨자 수(1), 뽑기 모양(카드 뒤집기·캡슐).
- **포인트·배지**: 참가 1점, 당첨 3점, `간식 기부천사`.

## 10. 자유 게시판 (완료)

- **게시판**: 그룹 전체 게시판과 팀별 게시판이 있습니다. 팀 게시판은 그 팀 구성원과 그룹 ADMIN만 봅니다.
- **글·댓글**: 글쓰기, 검색(제목·내용), 수정(작성자), 삭제(작성자·관리자), 댓글 작성·수정·삭제. 익명 글은 설정으로 허용합니다.
- **관리자**: 공지 고정과 숨김.
- **설정**: 그룹 게시판 사용, 익명 허용(꺼짐), 댓글 허용, 글 최대 글자 수(3000).
- **포인트·배지**: 글 2점, 댓글 1점, `글쓴이`, `댓글러`.

### 활동 기능 공통

- **설정**: 관리자(그룹 ADMIN·팀 ADMIN)가 `활동 기능 설정`에서 기능별 값을 바꾸고 `저장`을 눌러야 반영됩니다. 값은 `FeatureSetting`에 JSON으로 저장되고, 정의는 `packages/shared/src/feature-settings.ts`에 있습니다.
- **업로드**: `POST /uploads`로 올리면 `UPLOAD_DIR`(기본 `apps/server/uploads`)에 저장하고 `/uploads/<파일>`로 공개합니다. 주소는 추측하기 어려운 무작위 이름입니다.
- **샘플 데이터**: `scripts/feature/<기능>/`에 `generate-feature`, `generate-contents`, `delete-feature`, `delete-contents`가 있습니다(`rolling-paper`, `photo-mission`, `dinner-vote`, `random-survey`, `snack-draw`, `board`). `scripts/feature/generate.sh`는 모든 기능을 한 번에 승인합니다.
- **백업·복원**: `scripts/db-backup.sh`는 DB 덤프와 업로드 폴더를 함께 보관하고, `scripts/db-restore.sh`는 업로드를 되돌린 뒤 마이그레이션을 적용합니다.

## 11. 미니게임 (완료)

기능 승인 후 사용합니다. 구성원 화면은 `미니게임`, 설정은 `활동 기능 설정`입니다. 한 판이 10초~2분인 미니게임으로 팀 안에서, 팀끼리 겨룹니다.

- **게임 5종**: 감으로 10초(3초 뒤 시계가 사라짐), 반응속도(3회 평균, 미리 누르면 그 판 다시), 숫자 순서 터치(1~16), 기억력 시퀀스(단계별로 길어지고 빨라짐), 색깔 함정(글자 뜻이 아닌 색 고르기, 30초).
- **점수**: 원래 기록(ms·단계·개수)을 서버가 0~100점으로 바꿉니다. 정의는 `packages/shared/src/games.ts`에 있고, 범위를 벗어난 기록은 거절합니다.
- **한 판 흐름**: 소개 → 3·2·1 카운트다운 → 플레이 → 결과(점수 게이지, 우리 팀·그룹 순위, 개인 최고면 색종이) → 한 판 더 / 동료에게 자랑하기(결과 문구 복사).
- **반복 요소**: 오늘의 챌린지(날짜마다 바뀌는 게임), 연속 플레이 일수, 게임별 하루 플레이 수 제한, 개인 최고 기록, 지난주 챔피언·1위 팀.
- **관계 요소**: 홈에 `오늘 우리 팀 참여 n/m`과 아직 안 한 팀원을 보여 줍니다.
- **개인 랭킹 (주간)**: 우리 팀 / 그룹 전체. 사람마다 그 주의 최고 기록만 반영하고, 1~3위는 단상으로 보여 줍니다. 내 순위와 상위 %를 표시합니다. `종합`은 5개 게임 주간 최고점의 평균이며, 안 한 게임은 0점입니다.
- **팀 대결 (주간)**: 팀 점수 = 상위 K명 평균 × (100−w)% + 참여율 × w%. K = min(설정 상위 인원, 팀 인원의 절반 올림)이고, 기록이 K개보다 적으면 빈 자리는 0점입니다.
  - 5명 팀은 K=3, 50명 팀은 K=5입니다. 둘 다 같은 기준의 상위 평균으로 실력을 비교하므로 총점이 인원에 비례하지 않습니다.
  - 고수 1~2명만 해도 빈 자리가 0점이라 실력 점수가 낮고, 참여율도 낮아집니다.
  - 큰 팀은 상위 5명만 실력에 들어가므로 참여율이 낮아도 실력 점수는 불리하지 않고, 참여율 비중(w, 기본 30%)만큼만 영향을 받습니다.
  - 작은 팀은 참여율 100%를 쉽게 채우지만 w가 상한(80%)으로 묶여 있고, K명을 모두 채워야 실력 점수가 나옵니다.
- **설정**: 게임별 하루 최대 플레이 수(5), 참여율 비중(30%), 상위 인원(5), 오늘의 챌린지 표시.
- **포인트·배지**: 플레이한 날마다 1점(`gameDay`), `게임 메이트`(7일 플레이).
- **애니메이션**: CSS 키프레임(`globals.css`의 `wp-*`)으로 카드 팝인·호버 기울기, 그라데이션 흐름, 반짝임, 링 파동, 흔들림, 점수 게이지와 숫자 카운트업, 단상, 막대 차오름, 색종이를 넣었습니다. `prefers-reduced-motion` 설정을 따릅니다.
- **샘플 데이터**: `scripts/feature/mini-games/` (최근 2주 기록, 팀마다 참여율이 다름).
- **다음 후보**: 팀 보스 레이드(게임 점수를 대미지로 합산), 사진 빙고, AI 그림 전화게임 같은 비동기 턴제 게임은 아직 없습니다.
